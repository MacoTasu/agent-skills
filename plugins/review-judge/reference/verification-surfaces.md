# 検証サーフェス・カタログ

> 司法(`review-judge:judge`)が**直接 Read する参照**（ドメイン知識パックと同じ参照型）。
> 「変更の接触面(サーフェス) → そのサーフェスで**最低限要求する決定性証拠の"種類"**」を定める。
>
> **境界(deck 整合)**: この表＝**証拠の"種類"は汎用**（dotfiles）。**具体コマンドは各プロジェクトの
> 仕様(`./goals/<slug>.md`)で指定**＝プロダクト依存。本ファイルにコマンドは書かない。
>
> **用途**: 司法は契約の「検証サーフェス」宣言(無ければ差分から推定)を本表と突き合わせ、
> **要求証拠タイプが欠けていれば `RETRY`(証拠不足)** を返す＝**検証不足の検知**("done" 自己申告排除の二段目)。
>
> **拡張可能**: 新しい接触面が出たら行を足す。固定の分類ではない。

## サーフェス → 要求する決定性証拠タイプ

| サーフェス | 最低限要求する決定性証拠タイプ |
|---|---|
| **フロント**（UI/画面/コンポーネント） | ビルド／型／lint ＋ **視覚・挙動の確認（Playwright MCP・スクショ差分）** ／ a11y |
| **API**（HTTP/RPC/公開IF） | 契約・スキーマ(OpenAPI 等)整合／ステータス・エラー形／**後方互換チェック** |
| **データ・DB**（スキーマ/マイグレーション） | マイグレーション適用＋**ロールバック確認**／制約・整合／**データ損失なし** |
| **CLI・lib**（純ロジック） | unit テスト／構文・型チェック／境界値 |
| **infra・config** | 構文(plan/validate)／dry-run／**秘匿情報の非混入** |
| **docs のみ** | リンク・整合の確認／**コード変更を伴わないことの確認** |
| **横断（cross-cutting）** | 該当時必須: **security**（OWASP/入力検証/秘匿情報）・**perf**（N+1/退行） |
| **製品仕様 reconcile**（挙動を変える変更） | **製品仕様 `docs/specs/<feature>.md` の該当節が新挙動に更新**されている（goal の `product_spec` で宣言した anchor）。未更新なら RETRY＝reconcile 不足。挙動を変えない変更（docs のみ/テスト追加）は対象外 |

各行の証拠"種類"に対する**具体コマンドは契約側で指定**する（例: フロントの「視覚確認」を
Playwright のどのフローで取るか、は契約に書く）。

## 既存資産との接続

- **フロント**の「視覚・挙動の確認」: 本リポジトリは `.mcp.json` に **Playwright MCP** を持ち、
  `frontend-design` skill が UI 変更で自動発火する。フロントサーフェスの決定性証拠は
  Playwright MCP（スクショ・操作確認）で取得できる。
- 司法は証拠が**無い**ことを検知して RETRY するだけで、証拠を**取りに行く（自動実行）のは Phase 3**
  (driver)。本フェーズ(2.1)は「宣言を正とし、欠落を指摘する」ところまで。

## 司法での使い方（手順）

1. 契約の「## 検証サーフェス」宣言を読む。無ければ `git diff` の対象パス・拡張子から推定する。
2. 宣言/推定された各サーフェスについて、本表の「要求証拠タイプ」を引く。
3. 提供された証拠(c)にその種類が**揃っているか**照合する。
4. 揃っていない種類があれば `RETRY`(証拠不足)。理由に「どのサーフェスの何の証拠タイプが欠けるか」を明示。
5. 揃っていれば通常の二系統判定へ進む。
