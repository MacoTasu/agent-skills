# retro — マージ後に PR を振り返る

**書き手は `dev-crew:retro` エージェント 1 つ、入口は 3 つ。** PR 作成直後は指揮（`/conductor:dev`）が招集する
（`trigger=pr-created`）。マージ後は親の掃き出し（`conductor` の `parent-child.md`）が自動で下書きを作り、
このスキルは**同じ流れを人間が手で始める入口**（`trigger=post-merge`）。
PR 作成後に起きたこと（人間のレビュー指摘・追加コミット）も含めて振り返り、**新しいコメント**を積む。
先行する retro コメントは編集しない。

このスキルがするのは **招集と人間への確認だけ**。事実の収集・分類・提案・コメント・issue はエージェントが書く。

## 実行方法

```bash
/dev-crew:retro <PR番号>
```

## 手順

### 1. 引数の確認

PR 番号が無ければ、次を表示して止まる（推測で PR を選ばない）:

```
使い方: /dev-crew:retro <PR番号>
例: /dev-crew:retro 42
```

### 2. 下書きの招集

`dev-crew:retro` を Task で招集する（`subagent_type: dev-crew:retro`、`model: sonnet`）。渡すもの:

- 対象 PR 番号、`trigger=post-merge mode=draft`
- 契約に無かった書記の所見・契約合意後〜PR 作成までの人間の介入は、このスキルでは取れないので「不足」と明示して渡す
  （「介入: なし」と書かない。`interventions` は先行 retro があればその値に足し、無ければ `unknown` になる）

エージェントが PR から事実を集め、書き込みをせずに下書きを作る。返ってくるのは、下書きのディレクトリと、指標と項目ごとの予定。

### 3. 人間への確認

指標と項目の予定を短く要約して見せ、次の 4 択で聞く:

| 選択 | することと、その後 |
|---|---|
| **全部出す** | PR コメントと、予定の issue をすべて出す |
| **issue を選んで出す** | PR コメントは出し、issue は人間が選んだ項目だけ出す |
| **記録だけ** | 指標と項目を載せたコメントだけ出し、issue は作らない。末尾に「人間が issue 化を見送った: N 件」と書かれる |
| **あとで** | 何も出さず、ここで終わる |

### 4. 投稿の招集

「あとで」以外なら、`dev-crew:retro` を Task で招集する（`model: sonnet`）。
渡すもの: PR 番号、`trigger=post-merge mode=publish-draft`、下書きのディレクトリ、`choice=all` | `choice=items:1,3` | `choice=record-only`。
エージェントは下書きを**書き換えずに**、選ばれた範囲だけを投稿する（先に既存の post-merge コメントを確かめ、あれば何も書かない）。

### 5. 結果の表示

エージェントが返した項目ごとの結果（issue の URL か失敗の理由）と PR コメントの URL を表示して終わる。

## 失敗

どの段階でも続けられなければ、次の **1 行だけ**を表示して終わる。他に何も止めない（非ブロッキング）:

```
Retro: 未取得（<理由>）
```

## しないこと

- PR 番号を推測する（引数が無ければ案内して止まる）
- 集めた事実を自分で分類・評価する（エージェントの仕事）
- 人間の確認なしに投稿する（`publish-draft` の招集は確認の後だけ）
- 先行する retro コメントを編集する（新しいコメントを積む）
- PR を作る・マージする・コードを書く
