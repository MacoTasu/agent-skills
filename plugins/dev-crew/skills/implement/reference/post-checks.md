# 実装のあとの確認（後の確認）

> `dev-crew:implement` が、書き終えてから指揮に返すまでに行う確認の一覧。`SKILL.md` の手順から Read する。
> **`SKILL.md` が指した節（「spec-kit 契約」か「インライン契約」のどちらか）だけを、上から順に全部行う。もう一方の節は行わない。**
> `SKILL.md` の手順にあった記述をそのまま移したもので、ここで新しく決めたことは無い。
>
> **振り返り（retro）の提案の置き場。** 実装の手順で見つけるべきだったもの（retro の層 `行政`）への手当ては、この一覧の項目として足す。
> 足す・変えるのは、人間がこのファイルへの変更をマージしたときだけ。
> どの種類の手当てがどこに着地するかの索引は、本プラグイン同梱 `reference/failure-criteria.md`「着地の索引」。

## spec-kit 契約

番号は `SKILL.md`「手順（spec-kit 契約）」の続き（4.〜8.）。

4. **範囲外の変更** — 作業前の状態と比べて、変わったファイルを一覧にする。
   - `spec.md` と `.specify/memory/constitution.md` が変わっていたら元に戻し、指揮に報告する（正典は変えない）。
   - **ignore ファイル**（`.gitignore` / `.dockerignore` / `.npmignore` / `.eslintignore` / `.prettierignore` など）が、
     `tasks.md` のタスクに無いのに変わっていたら、**この実行で加わった変更だけを元に戻し**（この実行で新規作成されたものは削除し）、
     何を戻したかを報告する。元から存在した内容には触れない。
   - それ以外で `tasks.md` のタスクが指すファイル・`plan.md` の構成から外れる変更があれば、「スコープ外に触れた点」として報告する。
5. **自己レビュー** — 差分を読み返し、テスト・型・lint を実行する。直せるものは直す（自分の仕事の範囲で）。
6. **作り残しの点検（最大3回）** — `/speckit-converge` を実行する。仕様・計画・タスクとコードを突き合わせ、
   作り残しを `tasks.md` に **Convergence フェーズとして追記するだけ**の点検（コードは変えない）。
   追記されたら `SKILL.md` の手順 3.（書く）に戻って 4.・5. をやり直し、また点検する。「Converged」（追記なし）になるか、3回に達したら次へ。
   **Converged は完了の判定ではない**。行政の自己点検にすぎず、合否は司法が出す。
7. **見た目の証拠（UI に触れたとき）** — 同じディレクトリの `record-visual-evidence.md` を Read して従う。
   対象リポジトリの `.claude/visual-evidence.json` の `ui_paths` と差分の交わりで該当を決め、該当すれば録画シナリオを用意・更新して
   **after（自分の worktree）と before（merge-base の一時 worktree）を自分で録画**する。該当しなければ「該当なし」、
   撮れなければ「未録画（理由）」。結果は `SKILL.md`「返す形式」の `🎬 見た目の証拠（案）` に書く。添付と PR 作成は指揮の仕事。
8. **証拠表** — 基準ごとに、それを確かめる自動テストを特定して実行し、結果を記録する。
   テストの無い基準は隠さず「テストなし」と書く（司法はそれを RETRY にする）。
   ビルド・型・lint も実行する。実行できないものは「実行不能」と明記する（証拠なし扱い）。
