# reports — 集計の定義

窓口（`SKILL.md`）が「集計して」と頼まれたときの計算規則。タスク・状態・属性の意味は `conventions.md` に従う。
結果は会話で返すだけで、どこにも保存しない。

## 期間

- 「今年」「2026 年」= 1 月 1 日〜12 月 31 日。「先月」「10 月」= その月の 1 日〜末日。「今期」など会社ごとの区切りは利用者に範囲を聞く
- 期間に入るかどうかは**イベントの日付**で判定する
  - 完了（`☑`）→ 完了日（conventions 7 節）。月別の振り分けもこれ
  - 保留（`⏸`）→ 月末日（今どの月の見直し待ちか）
  - 中止（`✖`）→ 予定の日付そのまま（中止した日ではない。conventions 7 節）
- 削除された予定は読めないので集計に出ない（規約どおり）
- 読む範囲は conventions 10 節（過去 2 年〜未来 1 年）。それより古い期間を頼まれたら範囲を広げて読む
- 再開（保留→未完了）で `carried` は 0 に戻るので、再開後に完了したタスクの繰越実績は数字に残らない（v1 で受容）

## 指標

| 指標 | 定義 |
|---|---|
| 完了数 | 期間内の `☑` の件数 |
| 規模別完了数 | `impact` ごとの `☑` の件数（S / M / L）。`impact` が無いものは「規模不明」として別に数え、合計には含める |
| 繰越率 | `carried` ≥ 1 の `☑` の件数 ÷ 完了数。`carried` が無いものは 0 とみなす |
| 平均繰越回数 | `☑` の `carried` の平均（小数 1 桁） |
| 予定からのずれ | `☑` について、完了日 − `planned` の日数の平均と最大。`planned` が無い `☑`（予定日どおりに完了し、日付が一度も動いていない）はずれ 0 として含める |
| 保留数 | 期間内の `⏸` の件数 |
| 中止数 | 期間内の `✖` の件数 |
| 未完了の持ち越し | 期間末日時点で残っている `☐` の件数（期間が過去なら、期間末日より後の日付に `☐` があっても数えない） |

## 出し方

1. 期間と対象カレンダーを 1 行で明示する（「2026 年 1 月〜10 月、カレンダー『○○』」）
2. 指標を表で出す。月別を頼まれたら月ごとの行にする
3. 「規模 L の完了一覧」のような明細は、日付・本文・`carried` を 1 行ずつ
4. 規模不明があれば件数を示し、窓口で補完できることを 1 行で伝える（補完は利用者が頼んだときだけ行う）
5. 数字の根拠が必要と言われたら、数えた予定の一覧をそのまま見せられるようにしておく

## 注意

- 全件を読むこと。`list_events` 相当の操作はページングされるので、最後のページまで取る
- 期間が長いと件数が多い。読み切れないときは月ごとに分けて取る
- 集計のために予定を変更しない（`impact` の補完も、利用者が明示的に頼んだときだけ）
