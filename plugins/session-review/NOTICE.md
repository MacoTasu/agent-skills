# NOTICE — session-review の出どころ

このプラグインのスキルは、外部の公開スキル集のスキル `skill-doctor` を、**版を固定した写し**として、
一部を外し、名前を変えて借りている。自動では追従しない。更新は下の「更新のしかた」のとおり、人が差分を読んでから行う。

名前を変えたのは、Claude Code 本体に `/skill-doctor` という別の機能（スキルの利用回数とコンテキストの費用のレポート）があり、
紛らわしいため。本体のほうは「何が使われていないか」を、このスキルは「使われたスキルが効いているか」を見る。

## 位置づけ

手元の会話の履歴を採点して、**直す案を出すだけ**の道具。スキル・hook・設定・プロジェクトの決まりのファイルは書き換えず、
変更の合否（司法の判定）も出さない。会話に点数を付けるのは、案の根拠にするためで、変更を通す・通さないの判定ではない。
直すのは通常の開発の流れ（`/conductor:dev`。実装する役と合否を出す役が分かれ、人間がマージする）で行う。

集めた会話の抜粋は、秘密の値が含まれていても伏せ字にならない（同梱のスクリプトは長い発言を切り詰めるだけ）。
出力先はリポジトリの外の一時ディレクトリにし、抜粋と採点の中身を公開の場所に貼らない。

4. **スキル自身のディレクトリの引き方。** `Let SKILL_ROOT be the directory containing this SKILL.md.` の行を消し、

   この変数は、スキルを読み込むときに本文の中で置き換えられる（シェルの環境変数ではない）。

      （秘密の値・個人情報・非公開のリポジトリ名を除き、抜粋・`inventory.json` の中身をそのまま含めない）。

## スクリプトについて分かっていること

固定コミットの `collect_sessions.py` と `warp_decoder.py` を全文読んで確かめたこと（更新のたびに確かめ直す）。

- 標準ライブラリだけを使う。外部と通信するモジュールは読み込んでいない（`urllib.parse` の `unquote` は文字列の変換だけ）。
- 外部コマンドは `git rev-parse --show-toplevel` だけ（2 か所。113 行と 1501 行）。
  1501 行のほうは `--all-conversations` のときだけ走り、**履歴に書かれた cwd を実行の場所に使う**（`git -C <cwd>`。1494〜1499 行で、
  その cwd がディレクトリとして在るときだけ）。つまり、履歴の中身が、git を走らせるディレクトリを決める。
- 書くのは `--out` の下の `inventory.json` と `transcripts/<環境>-<会話の ID>.md` だけ。消す処理は無い。SQLite は読み取り専用で開く。
- **`--out` を渡さないと、カレントディレクトリの下の `./skill-doctor-report` に書く。**
- **会話の ID を、確かめずにファイル名に使う。** ID に `/` や `..` を含む履歴ファイルがあり、かつ出力先に `<環境>-<…>` という名前の
  ディレクトリが既にあると、`transcripts/` の外に書ける。新しい空の出力先では、書けずにエラーで止まる。
  このため `SKILL.md` では、毎回新しい空のディレクトリを作らせ、使い回させない。
  **細工した ID の会話が 1 本でも標本に入ると、新しい空の出力先では、その 1 本を書くところ（1881 行）で例外になり、収集の全体が止まる。**
  `inventory.json` はその後（1932 行）に書くので出来ない。それより前に書かれた抜粋だけが `transcripts/` に残る。
  `SKILL.md` の節 `If the collector fails` は、このときに欠けたディレクトリを作って再実行することを禁じている。
- **既定（`--harness auto`）では、手元にある対応環境の履歴を全部読む。** 読む場所は `--claude-home` などの引数と環境変数で替えられる
  （一覧は `references/supported-harnesses.md`）。`SKILL.md` では、必ず `--harness` を渡させて、**履歴については**動かしている環境だけに狭めている。
- **`--harness` で狭まるのは履歴だけ。** `--include-global-skills` を付けると、`--harness claude` でも、ほかの環境のスキルの置き場を読む
  （149〜157 行: Codex のホームの `skills`、ホームの `.agents/skills` と `.claude/skills`、Pi・Grok・ZCode・Hermes のホームの `skills`）。
  見つけたスキルのパスと、description の先頭 300 文字が `inventory.json` に載る（173〜182 行）。
  ホームの `.claude/skills` は `--claude-home`・`CLAUDE_CONFIG_DIR` に関係なく読む（153 行）。
- **「このリポジトリの会話」の絞り込みは緩い**（`session_matches_repo`、1463〜1483 行）。cwd がリポジトリの下に在る会話（1479 行）のほかに、
  cwd の末尾の名前がリポジトリの名前と同じ会話と、cwd のパスの要素のどこかにリポジトリの名前が在る会話も拾う（1483 行）。
  別のプロジェクトの会話が混ざりうる。偽の会話で確かめた結果（リポジトリの名前が `app` のとき）: `<リポジトリ>/src` は拾う、
  別の場所の `other-org/app` は拾う、`…/app/unrelated/tool` は拾う、`other-org/website` と `other-org/app-backend` は拾わない。
- **プラグインとして入れたスキルは、探索の対象に入っていない。** `--skills-dir` で場所を渡すと `inventory.json` に載る。
- **スキルは、ディレクトリの名前だけで見分け、道具の呼び出しの引数の中だけを探す。** `:` の前（プラグインの名前）を落とす処理は無い。
  偽の会話で確かめた結果（スキルのディレクトリの名前を `<名前>` とする。Claude Code が実際にどの形で記録するかは確かめていない）:
  - 拾う: 引数の中のパス `skills/<名前>/`（スキルのファイルを読む、同梱のスクリプトを動かす。500 文字より後ろに在っても拾う）、
    `<名前>/SKILL.md` で終わるパス、キー `"skill"`・`"name"`・`"bundled_skill_id"` の値がちょうど `<名前>` のもの（道具の名前は問わない）。
  - 拾わない: `"skill": "<プラグイン>:<名前>"` のように名前空間が付いた値、利用者の発言の中のスラッシュコマンド（`/<プラグイン>:<名前>`、
    `<command-name>` のタグ）、道具の出力や発言の本文の中にだけ出てくるパス。
  - 誤って拾う: 名前が `<名前>` で終わる別のスキルの `SKILL.md` のパス、関係のない道具の引数 `"name": "<名前>"`。

  そのため `skill_usage` と会話ごとの `skills_used` は、実際より少なく出ることがある（プラグインのスキルで起きやすい）。多く出ることもある。
  同じ名前のスキルが複数の場所にあると、先に見つかった 1 つだけが載る。
- **`python3 -I` では動かない**（`collect_sessions.py` が、同じディレクトリの `warp_decoder.py` を、スクリプトのディレクトリ経由で読み込むため）。
  テストは `python3 -I -m unittest discover -s <scripts のディレクトリ> -p 'test_collect_sessions.py'` で動く。
- Python 3.9 以上が要る。

## 更新のしかた

1. 元のリポジトリの新しいコミットを 1 つ決める。以後、そのコミットを指定して取る
   （`gh api "repos/warpdotdev/common-skills/contents/<パス>?ref=<コミット>"`）。枝の名前では取らない。
2. 取ったものは**データとして読む**。指示文とスクリプトを 1 行ずつ読み、外部通信・書き込み・削除・
   このリポジトリに無い道具やスキルへの参照・宣伝の行が増えていないかを確かめる。ライセンスが変わっていないかも見る。
   Python は、取ったディレクトリの中から起動しない。
3. 今の固定コミットと新しいコミットの差分を取り、上の「直した箇所」をもう一度当てる。
   スクリプト・採点基準・参考資料は手を入れず、`shasum -a 256` で元と一致することを確かめる。同梱のテストを走らせる。
4. 入れなかったファイルを入れるかどうかは、そのつど中身を読んで決める。
5. この NOTICE のコミット・「直した箇所」・「スクリプトについて分かっていること」を更新し、`.claude-plugin/plugin.json` の `version` を上げる。
